User supplied a WAV, JSON and CSV from capture
`66FDDD51-F801-4305-8AF3-600837C73D61`. Original files remain outside the repo;
no microphone audio is committed.

JSON reports iPhone Microphone, iOS 26.6.1 (23G83), mono, 48 kHz and a granted
5 ms I/O buffer. Device model and installed build ID aren't included in the report.
The user confirmed PhoneMic opened on the phone after installation with iloader.

Independent Python checks of the WAV and all CSV rows passed:

- RIFF sizes and data length valid; IEEE Float32 mono at 48 kHz.
- 2,345,760 frames, 48.87 seconds; matches JSON rendered/written frame counts.
- 9,774 CSV blocks, each 240 frames; matches callback count.
- No sequence gaps, sample-position gaps, sample-time jumps or nonmonotonic host times.
- Zero reported dropped/unwritten frames, render errors and oversized callbacks.
- Queue drained at stop; high water four blocks.
- All samples finite; RMS -45.51 dBFS, peak -15.95 dBFS; no samples at full scale.
- Nonzero audio present. Longest exact-zero span 2.42 ms; no claim of audible quality.

The reported max successful callback work is 0.126 ms. This is software work
timing, not input or end-to-end latency; physical latency remains unmeasured.

This run supports short capture/file continuity only. A later supplied take
passed the [five-minute check](m1-stability-2026-10-26.md), and the user confirmed
clear vocals. M1 acceptance is satisfied. Device model and interruption/route
checks remain unverified. M2 has not started.
