# M1 capture

Passed 2026-10-26: capture, readable PCM, five-minute foreground stability and
user-confirmed clarity. M2 has not started.

## Implementation Summary

RemoteIO microphone capture, permission handling, actual audio settings, local
Float32 WAV recording, level/capture counters, and exportable JSON/CSV diagnostics.
No streaming or monitoring.

## Architecture Changes

Swift configures capture and writes files on a serial worker. A small C11
callback and bounded SPSC queue avoid Swift runtime work in the callback.
Storage is preallocated; full queues reject new blocks and count lost frames.
See [capture decision](../decisions/0002-ios-capture.md).

## Files Changed

- `apps/ios/Native`: callback, queue and Swift bridge.
- `apps/ios/Sources`: capture service, permission/lifecycle model and recording UI.
- `apps/ios/Tests`, `tests/native`: synthetic WAV and queue tests.
- `scripts/test-native.sh`, `scripts/test-ios.sh`, CI: native sanitizers and simulator tests.
- `apps/ios/project.yml`: microphone purpose string, Files access and test target.

## Verification

Local Windows checks passed: `powershell -File scripts/verify.ps1` (seven Rust
tests, formatting, Clippy, receiver release build and smoke run).

MSVC C11 queue tests passed with `/std:c11 /experimental:c11atomics /W4 /WX`.
This local run covers boundary conditions, overflow, too-small output buffers,
maximum-sized PCM and repeated wraparound. An initial shell quoting error was
fixed by running the compiler through an ignored local command file in build/.

Mac CI runs `bash scripts/test-native.sh` with address/undefined-behavior
sanitizers, including 100,000 blocks passed between producer and consumer threads.
`bash scripts/test-ios.sh` selects an installed iPhone simulator for the active
SDK and runs the queued-PCM-to-WAV integration test. No test requests the mic.

[Final CI run](https://github.com/xxnoodl/covoo/actions/runs/40178811056) passed for
`707deb1`: Windows/Linux Rust checks, sanitized native queue tests, unsigned
iOS simulator/device builds, and the simulator PCM-to-WAV integration test.
The test writes 4,800 deterministic samples through the native queue, reopens
the Float32 WAV, and compares all samples and format/frame counts.
The initial run exposed main-actor notification warnings and a constant-folded
native lock-free check warning. Fixes keep notification handling on the main
actor and move the startup check into a helper. Full-screen mode resolves the
orientation warning. Those warnings are absent in the final run.
AppIntents metadata extraction reports no framework
dependency; this app doesn't use AppIntents.

## Hardware Validation

The user confirmed installation through iloader and that PhoneMic opened.
A supplied 48.87-second recording passed independent WAV/CSV checks: 48 kHz
mono Float32, no sequence/timestamp gaps, no dropped frames or render errors,
and finite nonzero samples without clipping. See the
[recording check](../testing/results/m1-2026-10-26.md).
A second supplied recording passed the five-minute foreground stability check:
344.565 seconds, 16,539,120 frames and 68,913 CSV blocks, with no sequence or
timestamp gaps, reported losses, render errors, nonfinite samples or clipping.
See the [stability check](../testing/results/m1-stability-2026-10-26.md).
The user confirmed clear vocals and acceptable quality. They report a lower
level than Apple Voice Memos and explicitly accept it; no gain change is requested.
This was a subjective comparison, not a calibrated level measurement.
Device model and installed build ID are not in the reports.
Interruption/route checks remain unverified.
No end-to-end latency measurement has been performed.

## Known Limitations

- 2026-10-26: user reports successful USB trust, but AltServer fails after Apple
  sign-in with error -80046. This initially blocked installation.
  Similar sign-in failures are reported in
  [AltStore issue 1840](https://github.com/altstoreio/AltStore/issues/1840).
  The user subsequently installed through iloader; this AltServer failure did
  not establish a PhoneMic binary or capture failure.

- Foreground only. Lock/background, interruption or a changed route stops the file.
- Manual restart creates a new recording. Media-service reset behavior needs hardware testing.
- No automatic storage cleanup. Disk/write errors stop recording and produce diagnostics where possible.
- Abrupt termination may leave an incomplete WAV; normal stop reopens and checks it.
- Measurement mode minimizes processing but doesn't prove raw ADC access.
- Callback work timing isn't input latency. No hardware performance claims.
- The manual macOS CI signing workflow remains untested; local iloader installation succeeded.
- On rare audio unit disposal failure, keep callback storage alive and require restart.
