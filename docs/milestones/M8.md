# M8 experimental audio enhancement and microphone modeling

Requested future research after the existing phases. Not started. This doesn't
authorize skipping physical gates, starting Android or changing the dry capture path.
M7 remains optional and requires separate authorization.

## Goals

1. Improve phone recordings toward studio-quality results in a studio or similarly
   suitable, quiet recording space.
2. Aim for a near-indistinguishable match to selected high-end microphones within
   defined recording setups. Success must be established by controlled listening
   and measurements, not assumed from a preset name.

Arbitrary rooms and uncontrolled recording conditions aren't the target. Define
the reference setup: phone model/input, orientation, working distance/range,
source type and level range, and suitable acoustic conditions. Calibration and
evaluation should reflect music recording in those conditions. Document the
supported envelope for each model rather than requiring a match everywhere.

## Architecture

Add an optional Windows processing stage after clock correction and before the
endpoint adapter. Keep it independent of capture and transport, with bypass and
a preserved dry recording. No required VST or external audio interface for users.
Local phone monitoring stays dry unless a later design explicitly changes it.

Evaluate conventional DSP and learned models. Live mode needs a measured added
latency budget; an optional offline mode can trade time for quality. Bound memory
and work, keep model loading/allocation off audio callbacks, and report processing
latency separately from network and physical end-to-end latency.

Provide two processing paths to evaluate: a causal, bounded live mode for DAW
tracking/monitoring and a higher-quality post-recording mode for algorithms that
need lookahead or more compute. Preserve the original take in both cases.
Budget CPU and memory separately from algorithmic buffering delay. Detect
processing overruns; never allow enhancement to accumulate unbounded latency.
DAW delay compensation can align tracks but can't remove the performer's live
monitoring delay. Upstream middleware processing isn't automatically visible as
a DAW plug-in delay; expose/report it through the endpoint integration where
supported and document configurations that need manual alignment.

## Experiments

- Enhancement: device-response correction, noise/reverb reduction, plosive and
  sibilance control, optional dynamics. Check transients and musical detail.
- Modeling: calibrated source correction followed by target-response modeling;
  investigate frequency, time, level-dependent and proximity behavior.
- Reference collection: controlled paired phone/reference-mic recordings with
  alignment, level calibration, documented room/placement and several levels.
  Reference microphones are research equipment, not a product dependency.
- Use permitted recordings/models. Review dataset, model and microphone-brand
  licensing before distributing named profiles.

## Validation

Compare dry phone, enhanced phone, modeled phone and real reference captures
using level-matched blind listening. Hold out voices/instruments and takes from
training/calibration; test source levels, distances and angles within the declared
setup, with another suitable recording space to check useful generalization.
No requirement to match in arbitrary noisy or reverberant rooms. Measure spectral/time
response differences, noise, distortion, clipping, artifacts, CPU and added latency.
Record listening-test uncertainty and supported conditions before making claims.

Mono phone capture lacks spatial information needed to recreate arbitrary
microphone polar patterns and room pickup. Missing or clipped source information
can only be estimated; plausible restoration isn't proof of the original waveform.
Publish limitations and keep enhancement optional if it damages the source.
