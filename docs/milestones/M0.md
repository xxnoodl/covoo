# M0 — Repository and build infrastructure

2026-10-25. Implementation delivered; **milestone acceptance is pending the iOS
macOS CI build**. No physical-device installation is claimed. M1 has not begun.

## Implementation Summary

Created a three-package, dependency-free Rust workspace, receiver CLI skeleton,
iOS 17 SwiftUI skeleton with XcodeGen specification, Windows/Linux Rust CI,
macOS unsigned simulator/device CI, and manual credential-driven development
signing workflow. Seven unit tests cover format validation, bounded FIFO behavior
and protocol serialization/validation. Naming is configurable.

## Architecture Changes

There was no preexisting implementation. ADR 0001 establishes native Swift
capture as the future iOS boundary, Rust format/buffer and codec contracts, and
independent transport, clock, jitter and endpoint adapters to be added when
implemented. The existing FIFO has exclusive ownership and is deliberately not
represented as a concurrent audio callback handoff. The CLI has no audio engine.
No external dependencies, crypto, networking or kernel code were introduced.

## Files Changed

- `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`: shared workspace/toolchain.
- `crates/audio-core`: validated mono format and preallocated bounded FIFO.
- `crates/audio-protocol`: provisional Float32LE header/payload codec and tests.
- `crates/windows-receiver`: build/availability console diagnostics.
- `apps/ios/project.yml`, `apps/ios/Sources/PhoneMicApp.swift`: native app skeleton.
- `.github/workflows/build.yml`: Rust checks, Windows artifact, unsigned iOS builds/logs.
- `.github/workflows/ios-signed.yml`, `scripts/build-ios-signed.sh`: manual signing.
- `scripts/verify.ps1`: reproducible local verification, including local Rust detection.
- `AGENTS.md`, `README.md`, `docs/decisions`, `docs/protocols`, `docs/testing`:
  scope rules, architecture, wire format and deployment setup.

## Known Limitations

- M0 acceptance remains open until the iOS app builds on macOS CI.
- Apple account/team, signing assets, registered device and Mac/device connection
  are not available or verified. An unsigned artifact is not installable proof.
- XcodeGen is installed via current Homebrew; runner Xcode is selected by its
  image. Exact versions are logged but not yet pinned. Pin after a successful
  macOS build establishes the tested tool combination.
- Protocol v1 is provisional and unauthenticated; do not send it on the network.
- The bounded FIFO is not the concurrent SPSC queue required for future capture.
- No performance claims, dashboard metrics or endpoint functionality are provided.
- No driver, Android, USB transport or ASIO work has started.

## Next Milestone

First close M0: run the macOS unsigned builds, inspect artifacts/results, fix any
build issues, and record the tested Xcode/XcodeGen versions. Then M1 can implement

## Required User Actions

1. Configure a GitHub remote and push this repository to run `Build and test`.
   Supply the failed logs if macOS CI fails; retain successful build/version logs.
2. Before device installation, follow `docs/testing/ios-deployment.md`: obtain
   an appropriate Apple account/team, choose bundle ID, provision the device,
   arrange a Mac that can connect to the phone, and enable Developer Mode.
3. Only if CI signing is wanted, populate the documented environment secrets and
   variables and manually run the signing workflow. Do not provide secrets in chat.
4. Report actual installation/test results when performed. No driver installation
   or system security changes are needed for M0.
