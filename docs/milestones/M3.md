reconnection and physical latency checks remain open.
M2 handoff was explicitly authorized with documented reliability limitations.

## Implementation Summary

Optional WASAPI shared output to an explicitly named existing endpoint, endpoint
enumeration, a DAW launcher, live queue/clock diagnostics and per-take live reports.
The compatible iPhone app doesn't change. WAV-only mode remains available.
VB-CABLE is an external Stage A dependency, not a finished covoo microphone.

## Architecture Changes

Authenticated packets independently enter bounded disk and live queues. Live
reordering uses 16 slots/20 ms and caps silence insertion at 50 ms. Larger gaps
omit counted frames. A lock-free rtrb queue feeds the output callback; no disk,
network, UI, logs or mutexes run there. Rubato preallocated sinc ASRC handles
nominal rate conversion and occupancy feedback, limited to 5000 ppm adjustment.
Emergency excess buffering is discarded/counts an overrun instead of accumulating
unbounded latency. The default target is 40 ms, configurable 20..100 ms; queue
capacity is 500 ms and backlog beyond three targets triggers recovery.

The adapter uses actual default endpoint rate/format, supports mono/stereo
float32/int16/int32, and copies mono into both stereo channels. Endpoint samples
are clamped to full scale; original Float32 archive samples aren't changed.
Each take gets fresh queue/resampler state. Shutdown pads the filter tail and
bounds drain waiting. Endpoint removal/render errors fail live routing explicitly,
without selecting another device or claiming reference audio was delivered.
See [decision](../decisions/0004-stage-a-output.md).

## Known Limitations

- External virtual cable needed for Stage A. No native covoo endpoint or installer.
- No ASIO, aggregation, USB or local iPhone monitoring changes.
- No endpoint failover; errors require reselecting/restarting the take.
- Initial UI is the technical console, not a graphical dashboard.
- CPU/memory telemetry, device notifications and detailed buffer history pending.
- Clock control has synthetic evidence only; physical drift/stability unverified.
- Default buffering prioritizes proving the route; latency targets aren't claimed.
- Receiver defaults to a one-hour process lifetime; extend `--seconds` for a
  longer session. Endpoint health appears in the console; the phone receives a
  live-output failure at finalization, not an immediate endpoint notification.
- Network outages lose audio outside the bounded recovery window. Long uninterrupted
  and reconnect acceptance from M2 remain open, with session/take tests prioritized.
