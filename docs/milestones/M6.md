hardware acceptance pending.

Optional wired phone monitoring is now implemented for CI/device validation.
See [local monitoring update](local-monitoring-update.md). Earlier descriptions
below reflect the preceding batch; they do not supersede this update. No phone
monitoring or route-safety hardware check has passed yet.

## Implementation and architecture

PC monitoring remains DAW-owned by default. A separate explicit wired-headphone
diagnostic launcher bypasses the DAW for comparisons. It does not provide a DAW
return stream or local phone monitoring.

Capture now feeds independent bounded archive/network queues directly from the
C callback. The writer no longer acts as the network producer. Either queue can
overflow independently without blocking the other. The callback still performs
only render, bounded copies and lock-free queue operations, without allocation,
network I/O, files, UI or logging. The C context borrows the network queue;
CaptureService retains its AudioStreamer owner through unit disposal, including
the existing failed-disposal state that prevents another start. Never invoke the
synthetic `submit()` producer while a callback owns that queue.

Recording reports identify this ingress path. Queue loss still counts as loss;
clear transport audio cannot hide a dropped local archive block. Local storage
and network reports must be compared independently after this change.

## Failure behavior and remaining work

| Failure | Current behavior | Later acceptance |
| --- | --- | --- |
| Permission denial | Visible error, no capture | Deny and re-enable microphone/local network |
| Background/lock | Capture deliberately stops | Confirm stop/finalization; background continuation not implemented |
| Call/audio interruption | Stop with reason; manual restart | Real call and audio-service reset |
| Route change | Stop when route signature changes | Unplug/replug and format changes |
| Network failure | Heartbeat/retry diagnostics; stream continuity not assumed | Outage during and between takes, saved local recovery |
| Endpoint removal | Explicit backend error; no default fallback | Remove selected output while active |
| Windows sleep/resume | No claimed seamless recovery | Resume, close/restart session, inspect files |
| Process termination | Final summaries may be absent; no continuity claim | Kill/restart and inspect incomplete files |
| Native-ingress ownership close | Reference model clears queue and identity | Future kernel cleanup and concurrency validation |

Optional local iPhone monitoring now has a full-duplex output path, independent
gain/mute and a route safety gate. Automated coverage is recorded in the linked
update. Physical monitoring and unplug safety remain unverified. Bluetooth is
not enabled; simultaneous Lightning transport/headphones remains unvalidated.
No automatic monitor resume after an interruption is promised.

## Screen-lock physical check

User locked the phone during file-only USB streaming. Capture stopped with
"App backgrounded. Recording stopped; receiver heartbeat timed out". Phone
`642ABBDC-DB5C-47A1-BDE9-6736BEF3F4B2` / receiver `33b69ee7e1d7a8be` both
contain 643,200 frames / 13.4 seconds at 48 kHz. Structural parsing and explicit
full payload comparison confirmed exact equality. Capture drops, render errors
and discontinuities were zero. PC received the sender's valid final summary,
reports complete continuity and finalized all 5,025 packets without gaps.

However, phone network_completed is false with network_stop_error "Receiver
heartbeat timed out". The normal uninterrupted-take verifier requires true and
would reject this pair; direct payload comparison is not a clean session pass.
Audio stop/preservation passed this observation, while control finalization did
not. Likely suspension/foreground heartbeat handling needs investigation; it is
not proven from these reports alone. Do not mark graceful lock handling fully
passed. Fix and retest completion acknowledgment; post-unlock fresh-take recovery
is a separate check. Background continuation remains unimplemented.

## Recovery update implementation

Added `TakeDelivery.swift` and tests to separate whole-take health from the
final session's stop acknowledgment. Reports retain interrupted-session evidence,
submitted/unconfirmed frame counters and an explicit PC comparison note. A final
saved session no longer clears earlier interruption evidence or displays a whole
take as saved without qualification. No unconfirmed-frame count is called actual
loss. Added explicit stop-ack state and bounded timeout even for callers without
an end completion closure.

Control waiting connections are retained with their deadline, and fatal-error
backoff is capped at two seconds. UIKit finite background execution is requested
synchronously on main before a capture transition; finalization then pauses idle
networking. Assertions end on completion, expiration, foreground return or model
teardown. Idle pause/resume avoids treating suspended heartbeat time as a new
capture failure. Recording still stops on background entry.

The Swift-to-Rust test now covers idle connection pause/resume and a loopback
proxy that deliberately breaks TLS during a take, followed by reconnection.
Physical behavior is unverified until the retests in todo.md. See
[the recovery decision](../decisions/0007-session-recovery.md).
